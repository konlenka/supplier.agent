## Independent review

The `qa` agent reviewed the diff three times. The first two verdicts were "fix first", and both were right.

- **Round 1.** My first fix for finding 1 did not work: one more staff text after a late order, or
  answering the new reminders, still sent a second order. Several new tests could not fail. That
  led to the rework above (the delivery rule, and a request that ends).
- **Round 2.** A count landing in the seconds while the 9:00 run was asking for it left a complete
  count, nothing to chase, and no order. A deadline text ("within 24 hours") was false for a late
  request. Fixed: the run re-checks after asking, and the follow-ups are timed from the request.
- **Round 3.** Verdict: merge after one named fix (nothing tested the Wednesday 9:00 trigger).
  Done, with two more it listed. **The round 3 fixes have not been re-reviewed.**

## Later (not fixed, one line each)

- Follow-up texts ignore the hour: a request made at 9:30pm books its reminder for 1:30am.
- The startup steps in `app.py` (`__main__`) and "follow-ups run under the order lock" have no test.
- A forced request while a delivery is pending answers every count with "still need a count" until the delivery is due.
- In the first week on a database with order history but no run log, a run can be skipped with no text.
- How many staff a text reached is logged for the follow-ups only, not for the 9:00 texts.
- "It's ordering day" is sent on any weekday a manual trigger asks for a count.
- A text from an unknown number gets a reply: each spam text costs an outbound SMS.
- Summer and holiday uplift is applied to the shortfall, not the target. Ask the owner which they meant.
- `/trigger` is still a GET with the key allowed in the URL; the port (5000) is set in code and the Railway mapping in the dashboard.
- Dependencies are unpinned; `pytest` is in the production requirements; `dry_run.py` writes to the real database.
- Staff and supplier numbers are written to Railway logs.
- Carried from 2 Oct: no approval step for the first runs, no PAUSE / RESUME text for staff.
